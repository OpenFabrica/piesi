没有把“线程更多”当作收益证据：测试了 1/4/8/18 线程；CPU 密集内容使用多核，原样存储的自动 I/O 并发上限为 4，显式线程参数可覆盖。缓冲回收实验没有稳定收益，已移除；XZ 默认级别强行拆小块虽快约两倍，却把同一测试包从约 2 MiB 增至约 10 MiB，因此恢复默认字典与块窗口。XZ / Zstandard 本次没有稳定的默认级别加速结论。

## 验收范围

- 原生窗口实际选择格式、反复收放高级选项、预设入口、密码不匹配/匹配，以及单文件 11 格式与目录 7 格式的菜单差异。
- 通过界面实际生成 tar.bz2，由系统 tar 解出并核对两项输入的 SHA-256。
- Swift 实际菜单对象验证 7/11 项、动作选择器及格式参数、旧请求兼容与所有格式 JSON 往返。
- 11 种创建格式的 CLI 创建、识别、校验、解压；ZIP / 7z 加密与错误密码、RAR 读取、编码和路径规则继续通过。
- TAR、tar.gz、tar.bz2、gz、bz2、xz、zst 的 64 MiB 输出分别用系统 tar/gzip/bzip2、xz、7-Zip 解码后核对原始 SHA-256。
- ZIP64：4 GiB+17 字节源文件、精确 0xffffffff 字节源文件，以及中央目录/条目偏移超过 4 GiB，均实际建包并由 7-Zip 校验。
- 单线程及输出失败不死锁、中途与末块取消、已有目标保留、失败无残件、CRC/尾块、AES 互通等回归。
- `cargo test --workspace --locked`：189 项通过；Clippy、字符串检查、Debug / Release arm64 构建与最终干净交付包的签名校验通过，App Intents 元数据完整。
